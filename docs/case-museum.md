# Case 001: the museum feed

The recommendation was to make the surveillance footage the first complete case, because it needs
identity impersonation, manipulated video, a compromised evidence source and an attempted false
attribution all at once. `scenario/museum.py` builds that case from synthetic parts and runs the
whole pipeline over it.

## What the case is

A camera feed shows a man at the museum at 14:07. A facility custody log puts him in a cell at
14:00. The camera's row manifest has lost a row since it was sealed, the clip's metadata has been
stripped, and its clock was set back a day. An operator credential authenticates and is not
permitted to write to that camera.

## What the pipeline concludes

| claim | grade | why |
| --- | --- | --- |
| media | corroborated | two temporal signals agree, and the custody chain is broken, which blocks `confirmed` |
| event | corroborated | the footage indicates synthesis **and** an independent record contradicts the event |
| record | confirmed | the sealed manifest no longer verifies and is one row short |
| concealment | corroborated | clock, provenance and container all show the shape of an attempt |
| access | unknown | the credential authenticated; permission to write is absent and unattributed |

Remove the custody log and the event claim drops to `unknown`, which is the ceiling from
`adjudicate.py` doing its job in a case rather than a unit test.

## The four "what should still exist" questions

Taken from defence-evasion thinking rather than from the show: for each concealment, what survives?

- **Timestamps altered.** The seal records when content existed, so a backdated file that is no
  longer the sealed content is a contradiction rather than a quiet edit.
- **Logs removed.** Per-row signatures cannot notice a deletion; the seal can, because it carries
  a count.
- **Metadata stripped.** Absence is reported as absence with its innocent explanation attached.
  Privacy tooling does this constantly.
- **Provenance dropped.** A file that was written by an encoder says so in its own tags, and a
  camera that never wrote a creation time cannot be distinguished from one whose tag was removed.
  The report says both.

## What this case does not establish

The footage is generated by this repository's synthesiser, so anything concluded about detection is
a statement about the method, not about footage from the world. The custody log is an input, and an
input can be wrong. There is no audio, no second camera and no telemetry, so the cross-modal
corroboration in the architecture diagram is still a diagram.

NIST, SWGDE, MITRE and CISA are design references for *how to evaluate*: unfamiliar generators,
degraded evidence, documented limitations, preserved originals and manipulated copies side by side.
Nothing here claims to satisfy any of them.
